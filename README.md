# VK ↔ Telegram bridge

Мост между беседами VK и группами Telegram: сообщения из одного мессенджера
дублируются в другой. Поддерживаются текст, фото, видео, документы, голосовые,
GIF, стикеры (как картинка/эмодзи). Автор показывается префиксом:
`[VK] Иван: текст` и `[TG] Иван: текст`.

Один бот/сообщество обслуживает **несколько независимых пар** «TG-чат ↔
VK-беседа» одновременно. Пары настраиваются прямо из Telegram кнопками (см.
[Управление чатами](#управление-чатами)).

> Боты не умеют публиковать сообщения под чужим именем/аватаром, поэтому
> используется текстовый префикс с именем отправителя.

```powershell

.\.venv\Scripts\Activate.ps1

```

## Настройка Telegram

1. Создай бота у [@BotFather](https://t.me/BotFather), получи `TG_BOT_TOKEN`.
2. **Отключи privacy mode**, иначе бот не увидит сообщения в группе:
   BotFather → `/setprivacy` → выбрать бота → **Disable**.
3. Добавь бота в нужную группу (рекомендуется сделать его админом).
4. Укажи `TG_ADMINS` — свой Telegram user id (можно несколько через запятую).
   Только эти люди могут связывать/отвязывать чаты командами. Узнать свой id
   можно у бота [@userinfobot](https://t.me/userinfobot).

`TG_CHAT_ID`/`VK_PEER_ID` в `.env` больше не обязательны — пары задаются
командой `/link` (см. ниже). Если они заданы, при первом запуске эта пара
автоматически попадёт в реестр (удобно для миграции со старой версии).

## Настройка VK

1. Создай сообщество (или используй существующее).
2. Управление → Настройки → **Работа с API** → создать ключ доступа
   с правами **«Сообщения»**, **«Фотографии»**, **«Документы»**
   (и **«Видео»** — для нативного видео) → это `VK_TOKEN`.
   Без Фото/Документов будет ошибка 15 при заливке вложений.
3. Там же → **Long Poll API** → включить, выбрать последнюю версию,
   в типах событий включить **«Входящее сообщение»** (`message_new`).
4. Настройки → **Возможности ботов** → включить, а также включить
   **«Возможность добавлять сообщество в беседы»**.
5. Добавь сообщество в нужную беседу и сделай его **администратором**
   беседы — иначе бот видит не все сообщения. Беседы, куда добавлено
   сообщество, потом сами появятся кнопками в `/link`.

## Управление чатами

Пары «TG-чат ↔ VK-беседа» настраиваются прямо из Telegram (только для
указанных в `TG_ADMINS`). Один TG-чат связывается с одной VK-беседой и наоборот.

1. Добавь бота в нужную **группу Telegram** и сообщество — в нужную **беседу VK**.
2. **Напиши любое сообщение в беседе VK** — так бот её «увидит». (Community-токен
   не умеет перечислять беседы, поэтому бот узнаёт их только из входящих
   сообщений. Беседа из `VK_PEER_ID`, если задана, доступна сразу.)
3. В группе TG напиши **`/link`** — бот покажет кнопки с увиденными беседами VK
   (уже связанные не предлагаются).
4. Нажми на нужную беседу — пара создана, сообщения пошли в обе стороны.

Ещё команды (тоже только для владельцев):
- **`/unlink`** — отвязать текущий чат;
- **`/status`** — показать все связанные пары;
- **`/help`** — краткая справка.

Связи и пары хранятся в `links.db` (SQLite) и переживают перезапуск.

## Что переносится

- Текст, фото, документы, аудио, голосовые, гео, контакты.
- **Видео:**
  - Без `VK_USER_TOKEN`: TG→VK = документ (mp4 играет в плеере VK),
    VK→TG = превью-кадр + ссылка. Нативное видео community-токену недоступно
    (`video.*` дают ошибку 5), а скрейп плеера блокирует анти-бот VK.
  - С `VK_USER_TOKEN` (токен личного аккаунта): TG→VK заливается настоящим
    видео через `video.save`, VK→TG скачивается через `video.get` и шлётся
    видеофайлом (до 50 МБ). См. `bridge/vk_user.py`.
  - Видео заливаются с `is_private=1` — они **не появляются в «Клипах»/каталоге
    видео сообщества** и доступны только по прямой ссылке (через `access_key`
    во вложении сообщения).

### Как получить VK_USER_TOKEN (для нативного видео)

Нужен токен личного VK-аккаунта (формально серая зона правил VK):
1. Открой страницу авторизации Kate Mobile (implicit flow) и разреши доступ.
2. Скопируй `access_token` из адресной строки после редиректа.
3. Впиши в `.env` как `VK_USER_TOKEN`. `group_id` для заливки определится сам.

Без этого токена всё, кроме нативного видео, работает как обычно.
- **Гифки:** VK→TG как анимация; TG→VK как документ (mp4).
- **Стикеры:** в обе стороны как картинка (анимированные TG-стикеры — по миниатюре).
- **Правки сообщений:** редактирование текста в Telegram отражается в VK
  (только текст, в пределах лимита VK в 24 часа; правка подписи к медиа не
  переносится, чтобы не стереть вложение). Обратное направление (VK→TG)
  **невозможно**: community-токену VK не присылает события правок чужих
  сообщений, а доступа к истории у него нет.
- **Личный префикс (`/prefix`):** любой участник может поставить себе
  префикс-эмодзи командой `/prefix 🕋` (в TG или VK). Тогда в пересланных
  сообщениях его имя показывается с этим префиксом: `[VK] 🕋Ирина Седойкина:`.
  Работает в обе стороны (TG→VK и VK→TG); префикс задаётся на каждой платформе
  отдельно. `/prefix` без аргумента — убрать. Хранится в `links.db`.
- **Ответы (reply):** нативные в обе стороны. Связи id сообщений хранятся в
  SQLite (`links.db`, авто-обрезка до ~50k записей, пара МБ), поэтому ответы
  работают и после перезапусков. Ответить можно и на медиа (фото/видео).
  Если связь всё же не нашлась — добавляется текстовая цитата оригинала.
- **Видео по ссылке:** если в сообщении (VK или TG) есть ссылка на
  TikTok / YouTube Shorts / Instagram Reels / X (Twitter), бот скачивает через
  **yt-dlp** и присылает его **ответом** на это сообщение — сразу в обоих
  чатах (в TG — видеофайлом, в VK — нативным видео при наличии `VK_USER_TOKEN`,
  иначе документом). Скачивание идёт фоном и не тормозит мост; видео крупнее
  50 МБ (лимит отдачи ботом в Telegram) пропускается. Список поддерживаемых
  доменов — в `bridge/video_dl.py` (`_SUPPORTED`), легко расширить.
  Для большинства сайтов ffmpeg не нужен (берётся готовый mp4).

  Если YouTube/Instagram отвечает «Sign in to confirm you're not a bot» или
  требует авторизации — передай боту куки через переменные окружения (`.env`):
  - `YTDLP_COOKIES_FROM_BROWSER=firefox` (или `chrome`, `edge`,
    `chrome:Profile 1`) — yt-dlp берёт куки прямо из браузера, где ты залогинен;
  - либо `YTDLP_COOKIES=C:\path\to\cookies.txt` — путь к экспортированному
    файлу cookies в формате Netscape.
  Обычно это не нужно: для YouTube уже используется TV-клиент, который
  проходит бот-проверку без кук.

## Крупные видео (>20 МБ): локальный Bot API сервер

Облачный `api.telegram.org` не даёт боту **скачивать** файлы больше 20 МБ и
**отправлять** больше 50 МБ — поэтому крупные видео между TG и VK не переносятся.
Лечится запуском собственного [локального Bot API сервера](https://core.telegram.org/bots/api#using-a-local-bot-api-server)
(лимиты поднимаются до 2 ГБ). Бот ходит в него, если задан `TG_API_URL`.

1. Получи `api_id` и `api_hash` на <https://my.telegram.org/apps> (любой свой
   Telegram-аккаунт → «API development tools»).
2. Подними сервер на `127.0.0.1:8081` (Docker или сборка из исходников
   [tdlib/telegram-bot-api](https://github.com/tdlib/telegram-bot-api)), передав
   `--api-id`/`--api-hash`.
3. Перед первым запуском против локального сервера разлогинь бота из облака
   (один раз): `curl https://api.telegram.org/bot<ТОКЕН>/logOut`.
4. В `.env` укажи `TG_API_URL=http://127.0.0.1:8081` и перезапусти бота.
   Флаг `TG_API_LOCAL=1` нужен только если сервер запущен с `--local`.

## Веб-приложение «альты» (Telegram Mini App, `/alt web`)

Команда **`/alt web`** присылает кнопку, открывающую мини-приложение Telegram со
списком всех альтов чата: **поиск** по названию, **фильтры по датам**, **превью**
(миниатюра видео), **аватарка и имя автора** (кто добавил альт через `/alt имя`).
Тап по альту отправляет его в чат — так же, как кнопка в `/alt list` (видео уходит
и в TG, и в парную VK-беседу). Превью и аватарки **не хранятся на диске**: байты
подгружаются по запросу (по `file_id` миниатюры в TG / `url` превью в VK; аватар —
`getUserProfilePhotos` или VK `photo_100`) и кешируются только в памяти с TTL.

Фича опциональна и включается, когда заданы `WEBAPP_PUBLIC_URL` и `WEBAPP_BOT_APP`.
Mini App требует **публичный HTTPS-URL с валидным сертификатом** (голый IP и
self-signed не подходят). Доступ к данным чата защищён: в ссылку зашит подписанный
(HMAC на токене бота) `tg_chat_id`, плюс на чтение/отправку проверяется подпись
Telegram `initData`.

Настройка (пример: бесплатный поддомен DuckDNS + Caddy + один порт):

1. **Домен на сервер.** Заведи бесплатный поддомен (напр. на
   <https://www.duckdns.org>) и направь его на IP сервера. Проверь, что
   `alts.example.duckdns.org` резолвится в IP и порты 80/443 открыты.
2. **HTTPS-прокси (Caddy).** Поставь Caddy (`apt install caddy`) и в `/etc/caddy/Caddyfile`:
   ```
   alts.example.duckdns.org {
       reverse_proxy 127.0.0.1:8090
   }
   ```
   `systemctl reload caddy` — Caddy сам выпустит и продлит сертификат Let's Encrypt.
3. **Mini App в @BotFather.** `/newapp` → выбери бота → **Web App URL** =
   `https://alts.example.duckdns.org/` → задай короткое имя (напр. `alts`).
4. **`.env`** бота:
   ```
   WEBAPP_PUBLIC_URL=https://alts.example.duckdns.org
   WEBAPP_BOT_APP=alts
   WEBAPP_PORT=8090
   ```
   Перезапусти бота. В логах появится «Веб-приложение альтов включено …».
   Теперь `/alt web` в любом чате моста открывает список.

## Instagram (директ → чат)

Отдельный аккаунт Instagram можно привязать к паре моста: все **входящие**
рилсы и сообщения из его директа автоматически льются в связанный TG-чат и его
VK-беседу. Рилсы **скачиваются и уходят полноценным видео** (тот же путь, что
для ссылок на рилс — через yt-dlp), сообщения — текстом с префиксом
`[IG] отправитель:`. Пересылка односторонняя (из чата в инсту ничего не идёт).

Требуется пакет `instagrapi` (в `requirements.txt`). Без него команды
`/instagram` отвечают, что фича недоступна, а мост работает как обычно.
Webhook'ов для личных аккаунтов у Instagram нет, поэтому директ **опрашивается**
раз в `INSTAGRAM_POLL_SECONDS` секунд (по умолчанию 45).

> ⚠️ Используется приватный API Instagram по cookie аккаунта (серая зона правил
> Instagram, как и `VK_USER_TOKEN`). Возможны челленджи/блокировки аккаунта —
> используй отдельный аккаунт, не основной.

**Как подключить** (команды — только для владельцев из `TG_ADMINS`):

1. **`/instagram add`** — *в личке с ботом*. Пришли cookie аккаунта: JSON-массив
   куки из браузера (расширение-экспортёр), объект `{"sessionid": "..."}` или
   просто строку `sessionid`. Можно тремя способами: аргументом команды, ответом
   команды на сообщение с cookie, либо файлом с подписью `/instagram add`. Бот
   проверит вход и добавит аккаунт в пул.
2. **`/instagram connect`** — *в нужной группе* (уже связанной с VK через `/link`).
   Бот покажет кнопки со **свободными** (ещё не привязанными) аккаунтами — выбери
   нужный. С этого момента его директ идёт в этот чат и его VK-беседу.
3. **`/instagram disconnect`** — отвязать аккаунт от чата.
4. **`/instagram list`** — все аккаунты пула и их привязки.

Аккаунты и привязки хранятся в `links.db` (cookie — в таблице `ig_accounts`).

## Ограничения

- Без локального Bot API сервера (см. выше) Telegram скачивает/отдаёт файлы
  **до 20 МБ** — крупнее не переносится.
- Instagram: пересылается только **входящий** директ (рилсы + текст); фото/
  голосовые/истории отмечаются короткой пометкой, но не скачиваются. Скачивание
  рилса подчиняется общему лимиту в 50 МБ и кукам yt-dlp (`cookies.txt`).
- Связи для reply хранятся в `links.db` (SQLite) и переживают перезапуск.
- Альбомы (несколько фото одним сообщением) приходят как отдельные сообщения.

## Структура

```
config.py            загрузка .env
bridge/main.py       запуск обоих ботов (asyncio.gather)
bridge/vk_bot.py     приём из VK, фильтры, имена  -> media
bridge/tg_bot.py     приём из Telegram, фильтры   -> media
bridge/media.py      перенос текста и вложений в обе стороны
bridge/formatting.py префиксы [VK]/[TG]
bridge/state.py      пары чатов + связи id сообщений TG<->VK (SQLite)
bridge/vk_upload.py  прямая загрузка фото/доков/голосовых в VK (community-токен)
bridge/vk_user.py    нативное видео через user-токен (video.get / video.save)
bridge/video_dl.py   скачивание видео по ссылке (yt-dlp): TikTok/Shorts/Reels
bridge/instagram_bot.py  наблюдатель за директом Instagram -> в пару (instagrapi)
bridge/alts.py       сохранённые видео («альты»): сохранение/выдача TG<->VK
bridge/webapp.py     Mini App /alt web: список альтов, превью, отправка (aiohttp)
```
